## 📂 Структура репозитория

Проект организован в строгом соответствии с регламентом курса: все исходные коды приложений вынесены в единый каталог автоматизации, а скомпилированные отчеты вместе с LaTeX-проектами распределены по соответствующим папкам лабораторных работ.

```text
containers-vch/
└── solutions/
    ├── assist-py/       # Исходный код разрабатываемого FastAPI-ассистента
    └── reports/         # Проекты отчетов и итоговые PDF-файлы
        ├── lab-1/       # Лабораторная работа №1
        ├── lab-2/       # Лабораторная работа №2
        └── lab-3/       # Лабораторная работа №3
```

## 🛠 Карта ведения лабораторных работ

Каждая лабораторная работа ведется и защищается в своей изолированной ветке Git, сохраняя полную хронологию и пошаговую историю коммитов.

*   `lab-1` — Верификация Docker-окружения, диагностика и базовый запуск изолированной СУБД PostgreSQL.
*   `lab-2` — Сборка образов, оптимизация слоев (`--no-cache-dir`), использование `.dockerignore` и внедрение `HEALTHCHECK`.
*   `lab-3` — Персистентное хранение данных (Volumes), внешнее конфигурирование (Bind Mount) и изоляция сервисов в Docker Network.
*   `lab-4` — *[В планах]* Многоконтейнерная оркестрация всей инфраструктуры через инструмент Docker Compose.
*   `lab-5` — *[В планах]* Развертывание и масштабирование микросервисов в локальном кластере Kubernetes.
*   `lab-6` — *[В планах]* Настройка CI/CD конвейера автоматизации сборки и тестирования образов.
